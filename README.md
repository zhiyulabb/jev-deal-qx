# Jev 双11购物通知（待真机验证）

1. **配置 Jev key。** 在 https://console.typesafe.ai 获取自己的 key。公开脚本第一行只保留 `apikey_xxx`。在圈 X 设备上执行一次性本地配置脚本：`$prefs.setValueForKey("你的真实key", "jev:api_key"); $done({});`，执行后删除该配置脚本，不上传、不打印 key。代码仓库：https://github.com/zhiyulabb/jev-deal-qx 。本地配置须通过圈 X 任务脚本运行环境执行，不是粘贴进重写规则。
2. **引用规则并获取慢慢买配置。** 圈 X「重写 → 引用」填写 `https://raw.githubusercontent.com/zhiyulabb/jev-deal-qx/main/jev_deal.conf`，启用并更新资源。完成第3步后，打开慢慢买 App「我的」，出现“慢慢买配置已保存”通知即可；参数只保存在本机，不显示内容、不推送 GitHub、不发给 Jev，只用于向慢慢买查询。接入方法参考 [githubdulong 模块](https://raw.githubusercontent.com/githubdulong/Script/master/Surge/jd_price2.sgmodule)及 [wf021325 查询脚本](https://raw.githubusercontent.com/wf021325/qx/master/js/jd_price.js)，请求流程重新实现，未复制其 HTML 注入或 Env 运行库。京东通过商品 ID 查询商品映射、价格走势、价格摘要；V1映射请求失败或返回信息不完整时，先用V2解析链接取得stteId，再尝试V2商品映射，共最多5次历史请求（V1失败1次＋V2链路4次），不循环重试；匹配失败或接口失效回退近90天本地浏览记录。第三方历史缓存6小时，返回哪些价格就显示哪些：历史最低、30/60/180天最低、618、双11与日期。优惠条件未核实，不能把第三方价格当作已验证的同条件到手价。淘宝目前仅有本地记录。通知先显示 Jev，再显示当前价格、历史价格与来源；不是修改商品页面。Jev 只接收提取的商品字段、价格摘要和本地记录，不接收慢慢买配置、请求签名、Cookie 或原始响应。首次没有可比记录、价格条件缺失或动作置信度低于0.55时建议为“信息不足”。同标题同现价且商品身份与配置一致的成功分析不会再次请求或通知；配置变更允许重新分析。
3. **启用 MitM 并验证。** 启用 `api.m.jd.com`、`trade-acs.m.taobao.com`、`in.m.jd.com`、`apapia-sqk-weblogic.manmanbuy.com`，安装并信任圈 X 证书，分流不用改。商品 JSON 提取最多六层；有标题、有效价和商品 ID 才分析，淘宝还要求 SKU ID。京东 HTML 入口只使用最近60秒捕获的对应 SKU 信息，不猜 HTML 中的价格或商品名称；单独命中 HTML 但无上下文会跳过。每次历史接口最多2.5秒，历史链路总预算9.5秒，Jev 最多5秒，总保护15秒；全部退出路径 `$done({})`，请求和响应 body 都不修改。等待分析可能延迟商品响应。模拟验证已覆盖签名、历史链路、商品错配、缓存、配置隔离、通知顺序、失败与超时；仍需你手机上的京东/慢慢买实际响应及真实 Jev key 验证。第三方非公开稳定 API，无当前可用性承诺。若 MitM 影响商品页，关闭本引用及新增主机解密，不绕证书。
